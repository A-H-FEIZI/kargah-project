TCP vs UDP — دو روش انتقال داده
اینا پروتکل‌های لایه transport هستن — یعنی چطور داده رو منتقل کنیم.
TCP — مطمئن ولی کندتر
مثل پیک موتوری که امضا میگیره — مطمئنی بسته رسیده.

هر packet رو تأیید میکنه
اگه گم شد دوباره میفرسته
ترتیب حفظ میشه
مثال: ایمیل، وب، دانلود فایل

UDP — سریع ولی بی‌ضمانت
مثل رادیو — میفرسته و اهمیتی نمیده رسید یا نه.

تأیید نمیکنه
سریع‌تره
مثال: بازی آنلاین، ویدیو کال، استریم


HTTP vs HTTPS — دو روش ارتباط وب
اینا روی TCP کار میکنن — یعنی چی منتقل میکنیم.
HTTP — ناامن
داده خام منتقل میشه — هرکی وسط راه باشه میتونه بخونه.
مرورگر → "password=1234" → سرور
هکر وسط راه: "password=1234" 👀
HTTPS — امن
داده رمزنگاری میشه — حتی اگه کسی ببینه نمیفهمه.
مرورگر → "x7$kP@#!" → سرور
هکر وسط راه: "x7$kP@#!" 🤷

TCP = پیک موتوری با رسید
یه بسته میفرستی — پیک موتوری میبره، امضا میگیره، برمیگرده بهت میگه "رسید!" اگه نرسید، دوباره میره. مطمئنه ولی یکم طول میکشه.

UDP = انداختن برگه از پنجره
یه برگه مینویسی و از پنجره میندازی بیرون — نمیدونی کی گرفت، نمیدونی رسید یا نه. سریعه ولی بی‌ضمانت.

چرا HTTP از TCP استفاده میکنه؟
وقتی یه صفحه وب باز میکنی، مرورگرت هزاران تیکه کوچیک داده دریافت میکنه — HTML، CSS، تصویر، و غیره.
اگه از UDP استفاده میکرد:
تیکه ۱: <html>
تیکه ۲: گم شد! ❌
تیکه ۳: </html>
نتیجه: صفحه خراب!
با TCP:
تیکه ۱: <html> ✅
تیکه ۲: گم شد → دوباره بفرست ✅
تیکه ۳: </html> ✅
نتیجه: صفحه کامل! 🎉

بازی آنلاین، ویدیو کال → UDP (سرعت مهمه، یه فریم گم بشه مهم نیست)
